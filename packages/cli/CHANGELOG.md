# Changelog

All notable changes to **`storyletengine`**, the Storylet Engine command-line tool, are
documented here. The CLI is released by tagging `cli-vX.Y.Z`, which drives
`.github/workflows/cli.yml`: its own pipeline, separate from Storyletter's bare `vX.Y.Z` tags
and from the engine ports.

Unlike Storyletter's, that workflow does **not** read this file: its release notes are written
into the workflow itself, and the binaries take their version from the tag. So a heading here
is a courtesy to whoever reads the history, not a gate on shipping. Write one anyway.

**This file is hand-written, and that is a consequence of a step we have not taken rather than
a choice.** Patter's equivalent is generated by Changesets, because `@patterkit/cli` is one of
the eight packages it publishes to npm and the changelog falls out of that flow. We publish
nothing to npm yet (public-split step 6a), so there is nothing to generate it. If that step is
ever taken, Changesets takes this file over, prepends its own `## X.Y.Z` / `### Patch Changes`
sections, and the hand-written entries below become the tail of its history. That works, but
the two styles will sit in one file, so it is better known in advance than discovered.

## [0.1.0] - 2026-08-30

The first public release, shipping as a standalone executable per platform: no Node, no npm,
nothing to install alongside it.

### Added

- **Project lifecycle**: `init` scaffolds a project (starter box, editor associations, git
  config) and `new box` adds a box from a kit.
- **The publish gate**: `validate` (bundle staleness and canonical form), `format` with a
  `--check` mode that writes nothing, for CI.
- **Compiling and publishing**: `export` to the `.storyletsc` bundle your game loads, with
  `--map` / `--no-map` overriding the project's map setting; `export-html` for one
  self-contained playable page; `export-xlsx` for the whole project as a readable workbook.
- **Playing without a game**: `peek` looks at the stock through the reference runtime and
  `deal` refreshes a hand, both with `--set`, `--seed` and `--deal-all`, so a scripted run can
  ask "what would come up here?" and get the same answer the engine gives.
- **Sending a project**: `pack` and `unpack`, including `unpack --merge --base` to fold a
  returned pack back into the project it came from.
- **Version control**: `merge`, a 3-way merge of storylets source by immutable id, resolving to
  OURS and leaving a `.storyletconflict` sidecar. `--path` names where that sidecar belongs
  when `-o` is a VCS temp file, which is what git's `%P` gives you.
- **Reading a project**: `resolve` finds an item by gameId, id or title and says which box, deck
  and shard holds it (the same lookup as Storyletter's `--at`); `links` reports which cards can
  turn which others on and off, from conditions and outcomes alone with no playthrough.
- **Coverage**: seeded random playthroughs reporting what your content can actually reach.

macOS binaries are Developer ID signed. Windows ships unsigned by policy, so SmartScreen asks
for "More info" then "Run anyway" on first run.

### Known gaps

- **No `--version`.** The binary cannot report which build it is, which makes "what are you
  running?" harder than it should be. Patter's CLI has the same gap, so this is a family-wide
  thing to fix in both rather than a divergence.
